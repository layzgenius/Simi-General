01 · Executive Summary

The gap is real — and no native iOS app is filling it.

The "songs like X" market is a $4.1 billion opportunity growing at 12.3% CAGR, served almost entirely by aging, web-only tools. The category leader — Chosic — pulls 4.1 million monthly visits almost entirely through organic search, proving the demand is massive and searchable. Yet no one has built a polished native iOS experience. Simi's window is open.

This report identifies five key findings that should directly shape Simi's build priorities and go-to-market strategy before a single line of code is finalized:

1. The competition is weak and web-locked. Chosic, Spotalike, Music-Map, Gnoosic, and TasteDive are all browser-based tools with mediocre mobile experiences. Every Noise at Once is effectively abandoned. None offer a URL-paste flow. None have a native iOS app.

2. Spotify killed the APIs Simi was designed around. In November 2024, Spotify deprecated Audio Features, Audio Analysis, and Recommendations endpoints for all new developers. The code as initially scaffolded will not work. Viable alternatives exist (SoundNet, Cyanite, Last.fm) and are detailed in §3.

3. The market is growing fast, skewed young, and mobile-first. 68% of smartphone users stream music daily. The 18–24 age group is the dominant music app demographic and also the primary "songs like X" searcher. iOS delivers higher revenue per user despite lower market share versus Android.

4. "Songs like X" is a proven SEO category with huge volume. Chosic derives 64% of all traffic from organic search alone, entirely from long-tail queries like "songs similar to sweater weather" and "songs like after dark." Simi's web presence and App Store listing should be engineered around this search intent from day one.

5. Three features separate Simi from every competitor: URL-paste UX, the Vibe Graph, and native iOS. No competitor offers any of these. Together they create a product that is meaningfully different — not just incrementally better.

Key Insight

Simi holds a 10/10 feature advantage on its three core differentiators versus a market leader (Chosic) with 4.1 million monthly visitors. The category is not won — it's waiting for a native mobile-first experience to claim it.

What Competitors Do Well (Don't Ignore)

Chosic's strength is its breadth of discovery surfaces. It has a similar song finder, playlist analyzer, music taste checker, genre finder, and artist map — all under one roof. Its 6:36 average session duration (very high for a utility tool) suggests users explore, not just one-and-done. Simi should note: the discovery rabbit hole keeps people engaged.

Last.fm's strength is its social graph. Years of scrobble data produce genre tags and similar-artist connections that are surprisingly accurate. Its crowd-sourced tagging system (e.g., "dream pop," "shoegaze") is richer and more specific than Spotify's genre taxonomy. Simi should continue leveraging this via the Last.fm API, which remains fully available.

Music-Map's strength is visual serendipity. Even though the tool is declining, its artist proximity map surfaces connections users didn't expect. The concept (spatial, visual) is worth incorporating into Simi's Vibe Graph.

03 · Critical Finding

Spotify shut the door on new developers. Here's how Simi gets in the window.

⚠ Action Required — Tech Stack Must Change

On November 27, 2024, Spotify deprecated Audio Features, Audio Analysis, Recommendations, and Related Artists API endpoints for all new developer applications. The current SpotifyService.swift code calls fetchAudioFeatures() and getRecommendations() — both of which will return 403 errors for a new Simi API key. This must be addressed before any testing begins.

What Was Removed

The deprecated endpoints were the exact ones Simi relies on most heavily:

EndpointWhat It DidStatus for New Apps
GET /audio-features/{id}BPM, energy, valence, danceability, key, mode✗ Deprecated
GET /recommendationsSeed-based similar track generation✗ Deprecated
GET /audio-analysis/{id}Deep rhythm & structure analysis✗ Deprecated
GET /artists/{id}/related-artistsSimilar artists✗ Deprecated
GET /tracks/{id}Basic track metadata (title, artist, album art)✓ Still available
GET /searchSearch for tracks by title/artist✓ Still available

Spotify's stated rationale was security, but the practical effect is protecting their music intelligence data from being used to train competing AI models. Apps with existing extended API access are unaffected — but any new developer app (including Simi) hits the wall.

The Fix: Alternative API Stack

Three strong alternatives cover everything Spotify was providing:

Option A — SoundNet Track Analysis API (Recommended for BPM/Features)

A drop-in replacement for Spotify's audio features endpoint. Send a track title and artist name (no file upload required), receive BPM, energy, mood, key, and more. Uses simple API key authentication. Described by developers as purpose-built for dynamic playlist generation, mood matching, and music visualizations. This is the most direct swap for Simi's needs.

Option B — Cyanite (Recommended for Vibe Graph + Genre)

Cyanite provides emotional analysis, genre classification, and similarity search — everything Spotify's audio features provided plus more. It's designed for B2B music tech use cases. Offers a Similarity Search that matches tracks by sound, vibe, and era with genre and BPM filters. More powerful than Spotify's API was, though potentially paid at scale.

Option C — Last.fm (Already in Stack — Use More Heavily)

Last.fm's track.getSimilar and artist.getSimilar endpoints remain free and fully functional. While Last.fm doesn't provide BPM directly, academic research has demonstrated that Spotify-style audio features can be accurately predicted from Last.fm tag vectors — meaning the genre tags Last.fm provides carry implicit audio feature signals. Use Last.fm as the primary similarity engine and SoundNet/Cyanite for audio feature enrichment.

Silver Lining

Spotify's deprecation froze many competing developers who relied on the same endpoints. Apps that were planning to compete with Simi using the Spotify recommendation engine are now in the same boat. Simi's pivot to a multi-API stack (Last.fm + SoundNet/Cyanite) actually creates a more resilient and more capable architecture than Spotify alone would have provided.

The iOS Advantage

Android holds 71% of the global music app market by user count, but iOS delivers significantly higher per-capita revenue — a well-established pattern across mobile categories. For a discovery tool with a freemium monetization model (free searches, premium for saved history or deeper analysis), iOS users are the higher-value cohort and the right place to establish product-market fit before expanding to Android.

The Audience Profile

Chosic's traffic data reveals who is searching for "songs like X": 18–24 year olds are the largest age group (dominant segment), and the audience is 59% male / 41% female. This is the exact demographic that:

• Discovers music through TikTok and short-form video (36% of this age group)
• Is frustrated by Spotify's "familiar territory" recommendations (documented complaint)
• Is comfortable sharing music via URL (this is their native behavior)
• Responds to visually distinctive, design-forward apps

Design Implication

Simi's visual identity — dark, minimal, gradient-heavy — is already aligned with this demographic's aesthetic preferences. Do not lighten it up. The polished dark theme is a feature, not a design choice to reconsider.

The "Algorithm Fatigue" Tailwind

A significant finding across multiple sources: there is growing documented frustration with Spotify's recommendation algorithm among exactly Simi's target users. The complaint is consistent — "it circles familiar territory" and "limits exposure to unusual or truly new artists." This is not a small minority opinion; it's a documented trend shaping the 2025–2026 music discovery landscape.

Simi's positioning as a discovery tool specifically for people who "already know what they like but want more" directly addresses this pain point. The framing "I need more songs like this" is a response to algorithm dissatisfaction.

05 · SEO Strategy

The "songs like X" search pattern is a category, not a keyword.

Chosic's entire growth story is a proof of concept for Simi's SEO strategy. 64.2% of Chosic's 4.1 million monthly visitors arrive via organic search. They built programmatic pages for individual songs — and Google sends them millions of searchers every month asking "songs like [title]."

The Programmatic Page Pattern

Chosic's URL structure for their most-trafficked content:

chosic.com/similar-songs/sweater-weather-by-the-neighbourhood/→ high volume
chosic.com/similar-songs/after-dark-by-mr-kitty/→ high volume
chosic.com/similar-songs/blinding-lights-by-the-weeknd/→ high volume

Each page is a simple, structured list of similar songs for a specific track. The page title matches the search query exactly. The content is functional and minimal. The SEO lift comes from the sheer volume of song-specific pages and the structural consistency.

Simi's SEO Architecture Plan

Phase 1 — App Store Optimization (ASO). Before a website exists, the App Store listing is Simi's first SEO surface. Title, subtitle, and keyword field should be engineered around: "find songs like this," "music similar to," "song vibe finder," "BPM music discovery." Screenshots should show the URL-paste moment and vibe graph — both visual differentiators that no competitor's screenshots show.

Phase 2 — Landing Page with Embedded Tool. A web version of Simi (even a simplified one) that generates "songs like X" results pages is the mechanism for capturing organic search. The page at simi.app/songs-like/[song-slug]/ captures every "songs like [title]" searcher who then sees a download CTA for the full iOS experience.

Phase 3 — Programmatic Content at Scale. For the top 10,000 songs on Spotify by popularity, generate dedicated pages. Each page shows: the song's BPM, genre, emotional fingerprint (energy/valence), and 10 similar songs. This alone is enough content to compete with Chosic in search results within 6–12 months, assuming reasonable domain authority is built.

TikTok as a Secondary SEO Surface

Multiple TikTok pages rank on Google for "songs similar to sweater weather" and "songs like after dark." Short-form video content tagged with these exact phrases functions as a parallel discovery channel. Simi should create TikTok content showing the app generating results for popular songs — each video is both distribution and an SEO signal.

Keyword Targeting for App Store

Based on observed search patterns and competitive analysis, the highest-value App Store keywords for Simi are: music discovery, find similar songs, song finder, songs like this, music like, BPM finder, vibe music, song recommender, music match, find new music.

The subtitle (shown in search results) should be: "Find Songs That Sound Like Yours" — this mirrors the exact search intent and is distinct from every competitor's App Store presence.

06 · Differentiation Playbook

How Simi wins — and what order to build it in.

Simi doesn't need to be better than Chosic at everything. It needs to be dramatically better at three things that Chosic cannot replicate without rebuilding from scratch: mobile-first UX, URL-paste input, and the Vibe Graph.

1
Fix the API Stack First (Before Anything Else)

Replace SpotifyService.swift audio features calls with SoundNet Track Analysis API. Update recommendations to route through Last.fm track.getSimilar. This is the prerequisite for everything else. The app cannot be tested until this is done.

2
Perfect the URL-Paste Moment

This is Simi's signature differentiator. The animation, the instant platform detection icon, the transition to results — it needs to feel magical. No competitor has this flow. Users share this moment on TikTok and Instagram. It's the viral mechanism.

3
Build the Vibe Graph

A 2D scatter plot of energy (y-axis) vs. valence/mood (x-axis) that places the source song and all recommendations as dots in emotional space. Tap any dot → play preview. Research confirms the energy-valence plane is scientifically validated for musical emotion classification. No competitor has visualized this for consumers. This is Simi's "wow" feature that gets shown in screenshots and demos.

4
Launch App Store with SEO-Engineered Listing

Title: "Simi — Find Songs Like Yours." Subtitle: "Paste any song link, discover more." Screenshots lead with URL-paste and Vibe Graph. Keywords tuned to "songs like," "music similar to," "find songs by vibe."

5
Launch a Web Landing Page with Embedded Tool

A fast, minimal web page at simi.app (or similar) that lets anyone search "songs like [title]" and generates a result page. Each result page is an SEO landing page. Primary CTA: "Get the full experience — download Simi for iOS."

6
Scale Programmatic SEO

Generate one page per popular song (top 10,000 Spotify tracks). Each page: BPM, genre, vibe summary, 10 similar songs with Spotify links. This is Chosic's playbook — execute it better with cleaner design and mobile-first pages that drive App Store conversions.

Positioning Statement

Simi's Core Value Proposition

"Paste any song. Find what it sounds like."

Simi is for people who hear a song they love and need 10 more just like it — right now. Not a playlist curated by an algorithm that's been watching you for years. Just: here's the song, here's what it sounds like, here are songs that feel the same.

Monetization Options (Based on Market Research)

Free tier: 5 searches per day, results list, basic vibe indicator. This is enough to demonstrate value and hook the user.

Simi Pro ($2.99/month or $19.99/year): Unlimited searches, full Vibe Graph, saved history, longer results lists (50 songs), audio preview playback in-app, genre deep-dive mode. The 18–24 demographic is the highest CAGR segment for music apps and pays for quality tools at this price point.

Revenue floor: Even at 1% conversion on 50,000 monthly active users, Pro generates $1,800/month — enough to cover API costs and App Store fees with margin to spare.

07 · Synthesis & Recommendations

The verdict: Simi is differentiated, the timing is right, and one critical fix is non-negotiable.

The research confirms Simi is entering a real market with genuine demand, weak incumbents, and no native iOS competitor. The concept is validated by Chosic's traffic numbers — 4.1 million people per month are already searching for exactly what Simi offers. The product direction (URL paste, BPM/genre matching, Vibe Graph) addresses gaps that none of the existing tools fill.

The single most important finding — and the one that must drive immediate action — is the Spotify API deprecation. Every line of code that calls /audio-features or /recommendations will silently fail when tested with a new API key. The revised architecture (Spotify for track lookup + SoundNet for audio features + Last.fm for similarity) is more robust, not less.

Priority Action List

Week 1 (Before any testing): Update SpotifyService.swift to remove deprecated endpoint calls. Integrate SoundNet Track Analysis API for BPM/energy/valence. Verify Last.fm similarity flow end-to-end.

Month 1: Complete Vibe Graph feature. Polish URL-paste animation. Internal beta on TestFlight.

Month 2: App Store submission. SEO-tuned listing. Simple landing page at simi.app with embedded search tool.

Month 3–6: Programmatic SEO page generation for top songs. TikTok content campaign showing the URL-paste moment. User feedback loop into feature roadmap.

What to Ignore From Competitors

Do not try to replicate Chosic's breadth — the "playlist analyzer," "music taste checker," and "random song picker" features dilute focus. Simi wins by being the best at one thing: "I have a song. Find me more like it." Depth beats breadth at launch.

Do not build a web-first version before the iOS app is solid. The market gap is native mobile. The web can come second and serve as the SEO surface — but Simi's identity should stay rooted in iOS.
